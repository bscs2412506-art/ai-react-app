# Project Instructions

## Project Stack

* React
* TypeScript
* Vite
* React Hook Form
* Zod
* CSS

## Project Structure

Keep React components organized inside the `src` directory. Use separate files for reusable components, validation logic, and application-level code.

## Coding Rules

1. Use TypeScript for all React components and avoid using `any` unless there is a clear reason.
2. Prefer functional React components and React hooks.
3. Keep form validation in a separate validation file using Zod.
4. Use React Hook Form for handling form state and validation.
5. Use clear, descriptive names for components, variables, and functions.
6. Keep components focused on a single responsibility.
7. Make the interface responsive for desktop and mobile screen sizes.
8. Do not remove existing functionality when modifying a component.
9. Test the application after making significant changes.
10. Keep the code readable and avoid unnecessary duplication.

## Development Workflow

Before making a significant change, understand the existing component structure. Make small changes, test them in the browser, and review any generated code before accepting it.

## Git Workflow

Use clear commit messages following the Conventional Commits style where practical, such as:

* `feat:` for new functionality
* `fix:` for bug fixes
* `refactor:` for code improvements
* `docs:` for documentation changes
